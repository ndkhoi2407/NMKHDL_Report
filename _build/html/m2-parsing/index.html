Milestone 2 — Hierarchical Parsing and Standardization¶

1. Objectives¶

Milestone 2 turns the raw LaTeX sources crawled in Milestone 1 into structured data:

  • Gather the files that are really part of each compilation, version by version.

  • Build a hierarchical tree of every version (document, sections, sentences, block formulas, figures, lists).

  • Standardize the content: LaTeX cleanup and math normalization.

  • Extract the references into BibTeX entries.

  • Deduplicate reference entries and full-text content across the versions of a publication.

  • Measure the success rate, running time, memory footprint and output size of the parser.

All numbers and figures on this page are generated while the book is compiled, from the small result files in m2_data/ (summary.json, papers.csv, samples.csv, tables_stats.json, kind_counts.json, failures.json, example.json).

2. Implementation¶

Audit baseline: official Milestone 2 specification.

2.1 Hierarchical parsing¶

Multi-file gathering. For every version, all .tex files are read and their comments are stripped first (an unescaped % starts a comment), so a commented-out \input is treated as plain text and never followed. The publication root is the file that contains \documentclass (and \begin{document}) and is not included by another file. \input, \include and \subfile are then expanded recursively, with a cycle and depth guard. Every file that is not reachable from the root is a redundant auxiliary file and is ignored, so the parse follows the selected compilation tree. This heuristic does not guarantee equivalence to a compiled PDF: unresolved includes are omitted and author macros are not expanded.

Hierarchy construction. Inside \begin{document}...\end{document} a block scanner finds sectioning commands, environments and display math. The sectioning commands that actually occur in a paper are ranked (part < chapter < section < subsection < subsubsection < paragraph < subparagraph) and mapped to consecutive levels, so the level of every heading is detected automatically: a paper that only uses \section and \subsubsection gets two heading levels. The abstract becomes an Abstract heading; unnumbered sections such as Acknowledgements and the appendices are kept; the References section and the thebibliography environment are excluded.

Leaf elements. The leaves of the tree are:

  • sentences – the prose of body text;

  • block formulas – the contents of equation, align, gather, multline, eqnarray, $$...$$ and \[...\];

  • figures – figure and table environments (a table is a kind of figure here) and stand-alone tabular, algorithm and similar floats. The LaTeX commands that define a figure (\includegraphics, \caption) are kept in the content.

itemize, enumerate and description become a list node whose item children contain their own sentences, formulas and figures; lists can be nested.

Sentence splitting. Text is split into paragraphs on blank lines and then into sentences at ., ? or ! followed by whitespace and a capital letter, a backslash, a dollar sign or a quote. A dot never splits a sentence inside mathematics or inside command arguments (\cite, \url, \footnote), after common abbreviations (e.g., i.e., Fig., Eq., et al.), after single-letter initials, or inside decimal numbers.

Versions without TeX. A version stored as an empty record by Milestone 1 (PDF only, other formats) is recorded with the status empty and produces no elements, so the coverage statistics and the tables reflect reality.

2.2 Standardization¶

Cleanup. Formatting commands without semantic content are removed (\centering, \midrule, \toprule, \hline, \vspace, \label, font-size and font-style switches, …), as is the float placement option such as [htbp]. Style wrappers such as \textbf{x} and \emph{x} are unwrapped in prose, and whitespace is normalized, so that formatting differences do not make identical texts look different.

Math normalization. All inline mathematics (\(...\), $...$) is written as $...$. All block mathematics ($$...$$, \[...\], equation, align, gather, multline, eqnarray) is written as \begin{equation}...\end{equation}; multi-line environments are wrapped in aligned or gathered inside it, so the result stays valid LaTeX. \label and \nonumber are dropped.

Reference extraction. Citations defined with \bibitem are converted to BibTeX entries with regular expressions: \newblock segments, a quoted title, or sentence splitting give the authors, title and venue, while the DOI, URL and year are matched separately; the entry type is inferred from the venue. The .bib files referenced by \bibliography are read by a small brace-aware parser. Each entry has a citation key, entry type, title, authors, year, DOI, journal and URL.

Reference deduplication. The entries of all versions of a publication (and the entries inside one version) are grouped with a union-find structure: two entries are the same reference when they share a DOI, a normalized title, or a citation key with a compatible title. One citation key is chosen for each group (the most frequent one, the newest version on ties), the \cite{} commands that use the dropped keys are renamed, and the fields of the duplicates are unionized by field: the newest non-empty value wins, and missing fields fall back to older entries. This does not concatenate conflicting author lists. A non-misc entry type takes priority over misc, even from an older version. Long normalized titles match without a year constraint; short non-empty titles require a year. The historical extraction used setdefault and could discard later fields under the same key. The corrected merge_bib_entry combines non-empty fields before cross-version unionization and retains conflicting values in bib_field_conflicts. These code fixes have not been applied to the historical corpus exports.

Full-text deduplication. After the \cite renaming, the identity of an element is its kind together with its cleaned text. Elements that match exactly across versions share one element_id in the elements table, and the hierarchy table holds one node-parent edge per version. Repeated identical text inside a single version gets distinct ids, so every version stays a tree.

Known limitations. Macros defined by the authors are not expanded, the \bibitem conversion is heuristic, and the text that follows a \paragraph{} heading belongs to that heading.

2.3 Execution¶

Publications are processed in parallel by a pool of worker processes, with a configurable per-publication alarm on platforms supporting SIGALRM. This timeout is not enforced by that mechanism on Windows, where this benchmark was measured. The status of each publication is saved periodically, so an interrupted run resumes where it stopped.

5.4 Interpreting the measurements¶

The worker-time column is elapsed time inside a worker, despite the summary field name avg_seconds_per_paper_cpu; it is not an operating-system CPU-time measurement. Parallel workers make its average different from wall time divided by publication count. Summed process-tree RSS may count shared memory more than once. Samples are taken periodically, so short-lived peaks may be missed.

Per-publication parsed.json files and merged JSONL tables are alternative representations of the same results. Their sizes are reported separately; neither is the size of the original downloaded corpus. The 331 empty versions include 17 missing source directories, not only PDF-only papers. The two no_root_file failures remain visible above. Exact-text deduplication does not detect paraphrases or semantic equivalence; bibliography merging remains heuristic.

The benchmark invokes parse.py without --export, so merged-table generation is not included in its wall time. The reported merged-table sizes describe existing artifacts; the summary alone does not establish when those tables were regenerated. Root-cause inspection of the two failures and executable checks of deduplication are in the evidence audit. These checks do not change historical results or prove every parsed sentence correct.
